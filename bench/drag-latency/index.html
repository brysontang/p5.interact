p5 draws on a refresh only if at least (1000 / target − 5) ms passed since the last draw, and frameRate() reports 1000 / the last gap. On a display that is not 60 Hz that skips refreshes in a pattern, so the gaps alternate and the number flickers. p5.interact sets frameRate(Infinity) after setup so no refresh is skipped; "p5 default pacing" calls frameRate(60) to show what plain p5 does.

"pointer age" is how old the last pointermove was when draw() ran. Around one frame (16 ms) is the browser doing its thing; more than that is something in the sketch.

Fill rate is the usual suspect: retina doubles both axes (4x the pixels), antialias multisamples each one, and p5 creates WEBGL contexts with preserveDrawingBuffer on, so the browser copies the frame instead of swapping it. Chrome on macOS honors the desynchronized hint for 2D canvases but not WebGL.
